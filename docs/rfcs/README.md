# RFC Process

Use an RFC before implementing changes that alter product or architecture boundaries, including:

- A new source format.
- A new storage or job model.
- A new standards/export engine.
- A rule DSL or UDF breaking change.
- A new high-risk automatic fix.

An RFC contains problem, goals/non-goals, proposal, alternatives, risks, migration, test plan and rollout. Once accepted, record the durable decision as an ADR and link both documents.
